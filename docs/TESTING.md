# Ручной чек-лист перед релизом

Автоматические тесты проверяют движок, правила и форматы протоколов. Всё,
что связано с ядром Linux, `nftables` и реальной сетью, проверяется только
руками — и обязательно **в виртуальной машине**, чтобы не потерять рабочее
интернет-соединение на основной машине.

## Подготовка

```bash
# Снапшот ВМ перед началом — ваша страховка
sudo systemctl stop proxy-for-ubuntud
sudo nft delete table inet pfu 2>/dev/null
sudo ip rule del fwmark 0x1 lookup 100 2>/dev/null
sudo ip route flush table 100 2>/dev/null
```

Снапшот делайте **до** каждого шага с «опасными» изменениями.

## 1. Установка

```bash
sudo apt install ./dist/proxy-for-ubuntu_0.1.0_amd64.deb

# Демон в автозапуске, но перехват не включён
systemctl is-enabled proxy-for-ubuntud
sudo systemctl start proxy-for-ubuntud    # поднять демон (перехват ещё выключен)
sudo pfu-cli doctor                       # nft, TUN, права, порты — всё ok

# Перехват ещё НЕ включён: это правильное поведение после установки
nft list table inet pfu 2>&1 | head -2   # ожидаем «No such file»
```

- [ ] Пакет ставится без ручной доводки зависимостей
- [ ] `pfu-cli doctor` не показывает критичных проблем
- [ ] Правил nftables после установки нет
- [ ] `ssh` работает (его нельзя сломать установкой пакета)

## 2. Первый запуск GUI

- [ ] `proxy-for-ubuntu` открывается, тёмная тема, все семь экранов в меню
- [ ] Если демон не запущен — понятное сообщение с командой

## 3. Проверка outbound'ов

Для каждого протокола, который вы собираетесь заявлять рабочим:

- [ ] Кнопка «Проверить» даёт задержку в мс, а не ошибку
- [ ] После выключения прокси-сервера «Проверить» показывает ошибку, а не

      об утечке DNS

## 4. Перехват и маршрутизация

```bash
# Включить перехват из GUI, затем:
nft list table inet pfu | head -20
ip rule show | grep fwmark
ip route show table 100
```

- [ ] После включения появляется таблица `inet pfu` и правило `fwmark 0x1`
- [ ] `curl https://ifconfig.me` показывает адрес прокси-сервера
- [ ] Правило `DOMAIN-SUFFIX,<ваш-домен>,DIRECT` действительно пускает напрямую
- [ ] Правило `REJECT` действительно обрывает соединение
- [ ] Порядок правил работает: перестановка двух правил меняет результат

### Проверка, что перехват работает

```bash
# Слушатели демона и правила
ss -ltn | grep 15000          # TCP REDIRECT
ss -lun | grep 15001          # UDP TPROXY (только форвардинг)
nft list table inet pfu | head -30
pfu-cli metrics               # счётчики соединений и байт
```

- [ ] `apt update` идёт через прокси (а не только браузер)
- [ ] `git clone` с внешнего хоста идёт через прокси
- [ ] `curl https://example.com` → 200, `pfu-cli metrics` после закрытия
      соединений показывает рост `connections` и байт
- [ ] Локальные DNS-запросы идут мимо демона (ожидаемо, см. §5):
      `ss -tunap | grep :53` не показывает процесс демона

## 5. DNS — известное ограничение

Локальный DNS **не перехватывается**: он относится к локальному UDP, а
`REDIRECT` не сохраняет настоящего получателя датаграммы (см.
`docs/ARCHITECTURE.md` §6.1). Запросы идут через системный резолвер,
`dns.strategy` на них не влияет, `fake-ip` не работает. Утечка DNS здесь —
не дефект, а описанное ограничение; оно исчезнет вместе с TUN.

- [ ] После `connect` DNS продолжает работать: `dig +short example.com`
- [ ] `dig +short example.com` возвращает настоящий адрес, а не `198.18.x.x`
- [ ] Ограничение описано в README, а не замалчивается

## 6. UDP и QUIC

Локальный UDP не перехватывается. Проверяется только форвардинг —
контейнеры, TCP при `intercept.docker: true`, UDP при `intercept.udp: tproxy`.

- [ ] `docker run --rm curlimages/curl -s https://ifconfig.me` показывает
      адрес прокси-сервера (TCP контейнера перехвачен)
- [ ] UDP из контейнера доходит до получателя, ответ приходит с настоящего
      порта, а не с 15001 (эхо-сервер на другом хосте)
- [ ] Локальный QUIC (`curl --http3 https://cloudflare.com`) идёт напрямую —
      ожидаемо до реализации TUN
- [ ] При прокси без поддержки UDP движок не теряет пакеты молча, а пишет
      в лог понятное сообщение

## 7. Apply и откат — самая важная часть

| Сценарий | Ожидание |
|---|---|
| Неверный порт в конфиге | Ошибка на этапе `validate`, система не тронута |
| Несуществующий прокси-сервер | Ошибка на этапе `probe`, система не тронута |
| Неправильный пароль | Ошибка `probe` с текстом от протокола, откат |
| Правило ссылается на несуществующий outbound | Ошибка `validate` |
| Синтаксическая ошибка YAML | Понятная ошибка с номером строки |
| Порт 15000 занят | Диагностика показывает занятый порт, Apply не идёт |
| Нет `nftables` | `doctor` показывает, что делать |

- [ ] Во всех случаях система остаётся в рабочем состоянии
- [ ] В уведомлении написано, что откат выполнен
- [ ] `sudo pfu-cli rules` показывает **старую** конфигурацию
- [ ] `nft list table inet pfu` соответствует старому состоянию

Ручная проверка отката при сбое health-check:

```bash
# Подсунуть заведомо неработающий маршрут и применить
sudo pfu-cli apply <<'YAML'
outbounds:
  - {name: DIRECT, type: direct}
  - {name: Битый, type: socks5h, server: 127.0.0.1, port: 1}
rules: [MATCH,Битый]
YAML
```

- [ ] Применение провалилось
- [ ] Интернет работает
- [ ] `nft list table inet pfu` не показывает новых правил

## 8. Устойчивость

- [ ] `sudo systemctl restart proxy-for-ubuntud` — трафик восстановился
- [ ] `sudo systemctl restart systemd-networkd` — правила переустановились
- [ ] `sudo systemctl restart NetworkManager` — то же
- [ ] Физическое отключение и включение сети — трафик пошёл
- [ ] `sudo reboot` — после автозапуска демона перехват в нужном состоянии
      (если был включён)
- [ ] Демон убит `kill -9` — после `Restart=always` поднялся сам, правила
      не остались в «полусломанном» состоянии

## 9. Удаление

```bash
sudo apt remove proxy-for-ubuntu
```

- [ ] `nft list table inet pfu` — таблицы нет
- [ ] `ip rule show | grep fwmark` — правила нет
- [ ] `ip route show table 100` — пусто
- [ ] **Интернет работает** (это главный пункт: если после удаления пакета
      сеть не поднялась — в `prerm` упущено)
- [ ] `sudo apt purge proxy-for-ubuntu` — конфиг и данные удалены

## 10. Безопасность

- [ ] Пароль в конфиге заменён на `${ПЕРЕМЕННУЮ}` в `/etc/proxy-for-ubuntu/env`
      и в логах не светится
- [ ] `journalctl -u proxy-for-ubuntud | grep -i password` — пусто
- [ ] `grep -r` по логам не находит UUID и паролей
- [ ] Экспорт профиля с «скрыть секреты» заменяет их на `***REDACTED***`
- [ ] В логах есть предупреждение про `skip_cert_verify: true`, если он включён
- [ ] GUI запущен от обычного пользователя: `ps -o user= -C proxy-for-ubuntu`
      показывает не root

## 11. Docker и виртуальные машины

Трафик контейнеров идёт через цепочку `FORWARD`, а не `OUTPUT`, поэтому
`intercept.docker: true` добавляет цепочку `nat prerouting` с `redirect`.

- [ ] С `intercept.docker: true` `docker run --rm curlimages/curl -s
      https://ifconfig.me` показывает адрес прокси-сервера
- [ ] Без флага трафик контейнеров идёт напрямую
- [ ] UDP контейнеров перехватывается через `tproxy` в `prerouting` и
      ответы приходят с настоящего порта
- [ ] Ограничение описано в README, а не замалчивается
