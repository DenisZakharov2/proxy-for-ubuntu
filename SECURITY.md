# Политика безопасности

## Поддерживаемые версии

| Версия | Поддерживается |
|---|:--:|
| 0.1.x | ✅ |

Проект молодой. Пока нет релизов с долгой поддержкой, принимаются отчёты об
уязвимостях в актуальной версии.

## Как сообщить об уязвимости

**Не открывайте публичный issue.** Используйте GitHub Security Advisories:

    https://github.com/DenisZakharov2011/proxy-for-ubuntu/security/advisories/new

Также можно написать напрямую: deniszakharov@msn.com

Ожидайте ответа в течение 7 дней. Подтверждение получения — 3 дня.

Пожалуйста, дайте время на выпуск исправления до публичного раскрытия.
Ориентир — 90 дней с момента подтверждения.

## Что считается уязвимостью

Приложение работает с root-правами и перехватывает весь трафик системы, поэтому
критичными считаются:

| Класс | Пример |
|---|---|
| Получение root из GUI | Эскалация привилегий: непривилегированный процесс заставляет демон выполнить произвольное действие |
| Утечка DNS | Домены, разрешённые для прокси, попадают в локальный резолвер при `fake-ip` или outbound с `remote_dns` |
| Утечка трафика | Пакеты, которые должны идти через прокси, выходят напрямую (или наоборот) |
| Целостность Apply | Неудачное применение оставляет систему без сети или с непредсказуемой маршрутизацией |
| Ложный откат | Демон сообщает об успешном откате, оставив изменения в системе |
| Секреты в логах | Пароль, UUID или ключ попадает в журнал, экспорт профиля или вывод ошибки |
| MITM | Проверка сертификата отключается без явного действия пользователя |
| Инъекция | Несанитизированное поле конфигурации позволяет изменить системные правила, путь записи файла или заголовок протокола |
| Зависание | Ошибка приводит к бесконечному ожиданию вместо отката (особенно в Apply) |
| Привилегированный ввод | Некорректный YAML или имя профиля позволяют записать файл вне каталога проекта |

## Что уязвимостью не является

- Протоколы `vless` и `vmess` не работают с конкретным Xray-сервером —
  это статус совместимости, задокументированный в
  [docs/PROTOCOLS.md](docs/PROTOCOLS.md), а не уязвимость.
- Трафик Docker-контейнеров не идёт через прокси — известное ограничение
  версии 0.1.0, описанное в README.
- `skip_cert_verify: true` отключает проверку сертификата. Это явный выбор
  пользователя, и в журнал пишется предупреждение. Сам по себе он не
  уязвимость, но его использование в чужих конфигах стоит обсудить в issue.
- Возможность принять неизвестный ключ SSH при первом подключении
  (`StrictHostKeyChecking=accept-new`) — поведение системного OpenSSH,
  выбранное сознательно, чтобы фоновый демон не зависал на вопросе.
