# Changelog

Все значимые изменения в этом проекте описываются здесь.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии следуют [Semantic Versioning](https://semver.org/lang/ru/).

## [0.3.0] - 2026-10-29

### Добавлено
- **TUN (`tun.enabled`).** Демон создаёт устройство `pfu0`, вешает на него
  адрес и маршрут по умолчанию в таблице 101, а nftables в хуке `mangle
  output` ставит метку `0x2`. Локальный трафик читается из `pfu0` и
  разбирается собственным userspace-стеком (`engine/tun/`): TCP — рукопожатие,
  передача данных, окно 65 535 байт, повторы по таймеру, закрытие по FIN;
  UDP — отдельный поток на каждую четвёрку адрес/порт. Так перехватывается
  локальный UDP (DNS, QUIC), который REDIRECT и TPROXY взять не могут. При
  включённом TUN REDIRECT для TCP не применяется.
- `tun.address` — адрес интерфейса, по умолчанию `198.18.0.1/15` (диапазон
  RFC 2544).
- `proxy-for-ubuntud --check` считает отсутствие `/dev/net/tun` проблемой
  только когда `tun.enabled: true`.
- **Перехват DNS (`dns.strategy: redir-host`).** При включённом TUN запрос к
  внешнему `:53` уходит через outbound, выбранный правилами, а из настоящего
  ответа демон запоминает «IP → домен» и подставляет имя в `Flow`. Правила
  `DOMAIN`, `DOMAIN-SUFFIX`, `GEOSITE` и прокси с `remote_dns` работают и для
  соединений, которые приложение открыло уже по адресу.
- **`HIJACK-DNS` отвечает по-настоящему.** Встроенный резолвер собирает ответ
  A/AAAA локально (системный резолвер, затем DoH с закреплёнными адресами),
  запрос наружу не уходит; при неудаче или для других типов записей —
  `SERVFAIL`, чтобы приложение сразу перешло к следующему серверу.

### Изменено
- `tun.mtu` по умолчанию 1500 вместо 9000: с большим MTU крупные датаграммы
  не проходят в обычную сеть, а TUN-стек их не фрагментирует.
- `tun.strict_route` удалено: поле никогда ничего не делало. Конфиг с ним
  теперь отклоняется при разборе — молча игнорировать настройку хуже, чем
  сказать о ней.
- `dns.strategy` по умолчанию `redir-host`; `fake-ip` отклоняется проверкой
  конфига с указанием на рабочее значение, а его реализация удалена: код
  выдавал синтетические адреса, но не был подключён к перехвату.
  `postinst` переводит существующий конфиг на `redir-host` и оставляет копию
  `config.yaml.pre-0.3.0`.
- `paths::dns_port()` удалён: отдельного DNS-порта нет, перехват идёт через
  TUN, а `HIJACK-DNS` отвечает на месте.

### Исправлено
- `proxy-for-ubuntud --check` читал конфиг строгим `Config::load`, а тот
  отвергает конфиг без единого прокси — то есть сразу после установки. Из-за
  `unwrap_or(false)` журнал писал «TUN выключен в конфиге» даже при
  `tun.enabled: true`, а отсутствующий `/dev/net/tun` не считался проблемой
  и в `--strict`. Теперь чтение идёт через `Config::load_for_read`; тест
  `load_for_read_sees_tun_in_a_direct_only_config`.
- `packaging/profiles/default.yaml` (его пакет ставит новым пользователям)
  содержал `tun.mtu: 9000`, хотя значением по умолчанию и документацией
  обещано 1500. Исправлено до сборки релизного пакета.

### Ограничения
- только IPv4; IPv6 идёт напрямую;
- запросы к `127.0.0.53` (systemd-resolved) не перехватываются: это loopback,
  он исключён из цепочек; приложения, которые сами ходят к внешнему DNS, —
  перехватываются;
- DNS over TCP проксируется, но в карту «IP → домен» не попадает;
- фрагментированные пакеты отбрасываются (пересборки нет);
- ICMP не проксируется;
- TCP без window scaling, SACK и таймстампов: на потерях медленнее стека ядра.

### Проверено
- netns-стенд `материалы сессии 15/`: UDP 1200 Б и TCP 256 КБ в обе стороны
  через `pfu0`, три прогона подряд; teardown не оставляет устройство,
  правило `fwmark 0x2` и таблицу `inet pfu`.
- netns-стенд `материалы сессии 16/`: DNS-ответ приходит через прокси, после
  него TCP к тому же адресу попадает под `DOMAIN-SUFFIX,…,REJECT` (до
  запроса — проходит), `HIJACK-DNS` отвечает `127.0.0.1` без выхода в сеть.
- **Живой прогон на хосте** (`материалы сессии 17/`): установлен пакет
  `0.3.0-1`, `pfu-cli connect` поднял `pfu0` и маршрут в таблице 101.
  TCP — `example.com` 200 и скачивание 3 МБ (745 КБ/с), счётчик `pfu0`
  `rx_bytes` вырос на 3 103 425 Б, то есть трафик шёл через устройство, а не
  мимо. UDP — `dig @1.1.1.1` и `@8.8.8.8` вернули адреса; QUIC-рукопожатие с
  `test.privateoctopus.com:4433` завершилось. `metrics` во время передачи:
  `connections: 2`, `FINAL/DIRECT` 5 559 351 Б. После `disconnect` порты,
  устройство, таблица 101 и правила `fwmark` убраны, сеть работает напрямую.
- 209 тестов `cargo test --lib`, `cargo clippy --all-targets -- -D warnings`.

## [0.2.0] - 2026-10-29

### Добавлено
- **Импорт ссылок и подписок.** `link.rs` разбирает `vless://`, `vmess://`,
  `ss://` (SIP002 и legacy), `trojan://`, `socks5://`, `http://`; `reality` и
  `grpc` отклоняются с причиной, а не молча теряются. `subscription.rs`
  понимает YAML, список ссылок и base64-список, возвращает `rejected[]` с
  номерами строк: одна битая строка не отменяет импорт.
- **IPC импорта:** `profile.import_uri`, `profile.import_links`,
  `subscription.preview`, `subscription.apply`, `subscription.list`,
  `subscription.refresh`, `subscription.remove`; реестр `subscriptions.json`
  и планировщик обновления по сроку.
- **GUI:** вставка списка ссылок, предпросмотр подписки («принято N,
  отклонено M») до записи в профиль, таблица подписок с кнопками «Обновить»
  и «Удалить».
- **`pfu-cli test-outbound`** — настоящий HTTP-обмен через `engine::outbound`
  с проверкой кода ответа.

### Исправлено
- **VMess переписан под протокол Xray.** Прошлая реализация не совпадала с
  сервером: authID шифровался самим uuid вместо
  `KDF16(cmdKey, "AES Auth ID Encryption")`, `cmdKey` считался без соли
  `c48619fe-…`, тело шло открытым текстом, заголовок ответа пропускался —
  Xray отвечал `invalid user`. Теперь KDF повторяет вложенный HMAC из Xray,
  тело идёт кадрами `len ‖ AEAD` со счётчиком nonce, ответный заголовок
  расшифровывается и сверяется по маркеру. Проверено против Xray 26.10.29:
  `vless` и `vmess` (AES-128-GCM и ChaCha20-Poly1305) отдают HTTP 200 через
  наш код.
- **`teardown` больше не пишет ERROR при первом старте**, когда FIB-таблицы
  100 ещё нет.
- **Секреты вне `Debug` и журнала:** пароли, UUID и passphrase редактируются,
  `${VAR}` без значения — ошибка разбора, `env` и `config.yaml` создаются с
  правами 0600, в юните `UMask=0077` и `RestrictAddressFamilies`.
- **GUI:** хелпер `ipc` переименован в `rpc` (WRY ставит свой `window.ipc`,
  из-за чего поставочное окно оставалось мёртвым), `enabled` берётся из
  `daemon.status`, в окне виден `engine_loaded`.

### CI
- `protocols.yml` проверяет `vless`/`vmess` через `pfu-cli test-outbound`,
  образ Xray закреплён по digest, матрица строится из фактических ответов.

### Тесты
- 182 модульных теста (было 139).

## [0.1.3] - 2026-10-26

### Исправлено
- **IPv6 больше не ломается при включённом перехвате.** Таблица `inet`
  покрывает оба семейства, а слушатели демона — только IPv4, поэтому
  IPv6-TCP уходил в `redirect to :15000` и соединение рвалось. В каждую
  цепочку добавлен `meta nfproto ipv6 return`: IPv6 идёт напрямую. Полной
  поддержки v6 по-прежнему нет.
- **Статистика по правилам пишется.** `Breakdown::record` вызывался только
  в тестах, поэтому `metrics.live` всегда отдавал пустые `active_rules` и
  `by_outbound`. Теперь TCP- и UDP-потоки пишут объём по правилу и
  outbound'у при закрытии.
- **`--check --strict` не требует `/dev/net/tun`.** На системе без модуля
  `tun` демон не стартовал, хотя TUN не реализован. Теперь строка
  информационная и запуск не блокирует.
- **`daemon.status` отдаёт `engine_loaded`.** `config_valid` на свежем
  демоне был `false` и читался как «битый конфиг»; отдельное поле
  показывает, собран ли движок.
- **Релиз: `.deb` грузит только джоба ubuntu-22.04.** Оба matrix-джоба
  клали файл с одинаковым именем, и в релиз попадал последний.

### Документация
- README, ARCHITECTURE (RU/EN) и IPC: IPv6 идёт напрямую, `/dev/net/tun`
  не обязателен, поле `engine_loaded`.
- ROADMAP: статусы сверены с кодом — №2, №6, №9–№12, №15–№17 закрыты,
  №1 и №8 ждут e2e-теста протоколов.

### Тесты
- 139 модульных тестов (было 137): IPv6-guard и имя сработавшего правила.

## [0.1.1] - 2026-10-11

Исправления по итогам проверки на реальной установке (issue #1).

### Исправлено
- **GUI не мог подключиться к демону: `Permission denied`.** postinst создавал
  группу `proxy-for-ubuntu`, но никогда не добавлял в неё пользователя рабочего
  стола. Сокет принадлежит группе, и обычный пользователь в неё не входил.
  Теперь пользователь определяется через `SUDO_USER`, затем через активную
  сессию logind, и добавляется в группу. Каталог `/run/proxy-for-ubuntu`
  переведён с 0755 на 0750 с группой демона: иначе войти в каталог с сокетом
  было нельзя.
- **postinst врал об успехе.** Сообщение «пользователь добавлен в группу»
  печаталось даже тогда, когда `usermod` падал. Теперь оно выводится только
  при реальном успехе, а при неудаче печатается причина в stderr и точная
  команда для ручного исправления.
- **Приложение могло молча работать на подставных данных.** В
  `tauri.conf.json` не был выставлен `withGlobalTauri`, поэтому
  `window.__TAURI__` не появлялся, фронтенд считал себя запущенным вне
  оболочки и показывал мок-данные, ни разу не обратившись к демону. Флаг
  включён; кроме того, вне оболочки теперь показывается заметная плашка.
- **Пустое окно на LXQt/Xfce (Openbox + picom).** WebKitGTK на этом
  окружении не рисует содержимое webview. Приложение само выставляет
  `WEBKIT_DISABLE_DMABUF_RENDERER=1` и `WEBKIT_DISABLE_COMPOSITING_MODE=1`
  до инициализации GTK. Приложение больше не паникует при неудачном открытии
  окна, а объясняет причину и предлагает `LIBGL_ALWAYS_SOFTWARE=1`.
- **CSP был строже, чем требует Tauri:** не были разрешены схемы `ipc:` и
  `http://ipc.localhost`, по которым Tauri 2 ходит к бэкенду.
- **Поиск по журналу.** Метод `log.search` был описан в `docs/IPC.md`, но не
  реализован. Реализован, добавлен в GUI и покрыт тестом. При этом тест
  обнаружил, что `to_ascii_lowercase` не понижает кириллицу — поиск по
  русским сообщениям не работал бы; заменено на `to_lowercase`.
- **`log.export` падал** на пути без каталога (`"log.txt"`) из-за
  `path.parent().unwrap()`.
- `postinst` больше не ошибается в разборе вывода `loginctl`: SEAT — это
  четвёртое поле, а не третье, из-за чего выбиралась сессия root.

### Добавлено
- `proxy-for-ubuntu --diagnose` — окружение WebKit, графической сессии и
  состояние сокета, для диагностики пустого окна и отказа в доступе.
- `proxy-for-ubuntu --version` — раньше команда открывала окно.
- Поле поиска в журнале.
- 125 модульных тестов (было 124).

## [0.1.2] - 2026-10-26

### Добавлено
- **Перехват трафика.** TCP системы ядро перенаправляет в слушатель демона
  (`nftables` REDIRECT → `0.0.0.0:15000`, настоящий получатель читается из
  `SO_ORIGINAL_DST`); UDP форвардинга — через TPROXY (`:15001`,
  `IP_ORIGDSTADDR`; на каждый поток создаётся сокет с `IP_TRANSPARENT` и
  `SO_REUSEPORT`, поэтому ответ уходит с настоящего порта). TCP контейнеров
  перехватывается при `intercept.docker: true`.
- `system.diagnose` показывает число открытых дескрипторов и soft-лимит.

### Исправлено
- **Набор nftables собирался с недопустимым синтаксисом** (элементы `set`
  перечислялись списком вместо `elements = { … }`) — `connect` падал на
  разборе правил.
- **Демону не хватало файловых дескрипторов:** в юните
  `LimitNOFILE=65536`; при `EMFILE`/`ENFILE` цикл accept спит секунду и
  пишет одно предупреждение в секунду вместо десятков тысяч строк.
- **После `disconnect` UDP-сокет жил до 60 с**, а открытые TCP-соединения
  не рвались: `Capture` получил `CancellationToken`, `stop()` отменяет
  задачи и дожидается закрытия сокетов.
- **`teardown` не был идемпотентен и глотал ошибки:** теперь удаляет все
  свои `ip rule`, проверяет результат, ждёт освобождения таблицы и
  возвращает `Error::Apply` со списком неудач; правило не дублируется.
- **TPROXY забирал трафик, адресованный самой машине** (mDNS и прочие
  пакеты к локальным адресам — десятки тысяч датаграмм в журнале):
  добавлены `fib daddr type local`, multicast и broadcast.
- **Ответы UDP уходили с порта 15001** вместо настоящего — клиент их
  отбрасывал.
- **Повторный `connect`** падал с `Address already in use` и оставлял
  `enabled: true` без слушателей; теперь отвечает, что перехват уже включён.
- **`intercept.tcp: tproxy` принимался, но работал как `redirect`** —
  значение молча игнорировалось. Теперь валидация отклоняет его с
  подсказкой, и в настройках GUI этого варианта нет.
- Документация приведена в соответствие с кодом: TUN помечен как
  нереализованный, описано, что локальный UDP (DNS, QUIC) не
  перехватывается и `dns.strategy: fake-ip` пока не работает.

- **systemd-юнит не запускался: `ExecStartPre` падал с `Connection refused`.**
  `ExecStartPre=/usr/bin/pfu-cli doctor --strict` ходил к управляющему сокету
  по IPC, а сокет создаёт сам демон — на этом шаге его ещё нет. Заменено на
  `proxy-for-ubuntud --check --strict`: та же проверка окружения, но без
  демона. Заодно `--strict` теперь читается как отдельный аргумент
  (`--check --strict`, именно так его передаёт systemd) и считает отсутствие
  root проблемой.
- **`pfu-cli config` печатал ответ демона целиком** (`{"config": ...}`), а не
  сам конфиг, поэтому документированный маршрут `pfu-cli config > my.yaml` →
  правка → `apply < my.yaml` не работал: `apply` и `validate` такой файл не
  принимали. Теперь команда печатает конфиг в YAML.
- **GUI не мог подключиться к демону: `Permission denied`.** postinst создавал
  группу `proxy-for-ubuntu`, но никогда не добавлял в неё пользователя рабочего
  стола. Сокет принадлежит группе, и обычный пользователь в неё не входил.
  Теперь пользователь определяется через `SUDO_USER`, затем через активную
  сессию logind, и добавляется в группу; если определить не удалось —
  выводится точная команда. Каталог `/run/proxy-for-ubuntu` переведён с 0755
  на 0750 с группой демона: иначе пройти в каталог с сокетом было нельзя.
- **Приложение могло молча работать на подставных данных.** В
  `tauri.conf.json` не был выставлен `withGlobalTauri`, поэтому
  `window.__TAURI__` не появлялся, фронтенд считал себя запущенным вне
  оболочки и показывал мок-данные, ни разу не обратившись к демону. Флаг
  включён; кроме того, вне оболочки теперь показывается заметная плашка.
- **Пустое окно на LXQt/Xfce (Openbox + picom).** WebKitGTK на этом
  окружении не рисует содержимое webview. Приложение само выставляет
  `WEBKIT_DISABLE_DMABUF_RENDERER=1` и `WEBKIT_DISABLE_COMPOSITING_MODE=1`
  до инициализации GTK. Добавлена команда `proxy-for-ubuntu --diagnose`,
  выводящая окружение WebKit, графической сессии и состояние сокета.
- CSP в `tauri.conf.json` был строже, чем требуется Tauri: не были разрешены
  схемы `ipc:`/`http://ipc.localhost`, по которым Tauri 2 ходит к бэкенду.

### Исправлено (ранее)
- `Policy` сериализовался именем варианта Rust (`final: Direct`) вместо
  Clash-имени (`final: DIRECT`). Конфиг, сохранённый приложением, читался
  обратно корректно, но выглядел не так, как описан в документации.
- Отчёт о применении больше не врёт: появилось поле `system_touched`,
  отличающее «систему не трогали» (сбой на `validate`/`probe`) от
  «система изменена и откачена». Раньше GUI в обоих случаях писал
  «система возвращена в прежнее состояние».
- `clippy -D warnings` и `cargo fmt --check` проходят: устранены 2 ошибки
  («цикл, который не крутится») и 22 предупреждения, включая нарушение
  MSRV — `AtomicU64::try_update` требует Rust 1.95 при заявленных 1.77.
- Убрана мёртвая ветка в `aes_ecb_block` (vmess) и одинаковые ветви `if`
  в SOCKS5-UDP: обе маскировали ошибку копированием кода.
- Битая ссылка на пример конфигурации в `docs/ARCHITECTURE.md` и
  `docs/CONFIG.md` — файл лежит в `packaging/profiles/`.

### Добавлено
- 124 модульных теста (было 123): проверка сериализации `Policy`.

## [0.1.0] - 2026-10-06

Первый публичный релиз.

### Добавлено
- **Ядро маршрутизации.** Перехват системного TCP через `REDIRECT` и UDP
  через `TPROXY` с политической маршрутизацией по метке; маршруты системы
  не изменяются. *Фактически слушатели и правила появились только в
  `[Unreleased]`; в 0.1.0 трафик не перехватывался.*
- **Rule engine в духе Clash.** Первое совпадение выигрывает. Типы:
  `DOMAIN`, `DOMAIN-SUFFIX`, `DOMAIN-KEYWORD`, `DOMAIN-REGEX`, `IP-CIDR`,
  `GEOIP`, `GEOSITE`, `DST-PORT`, `SRC-PORT`, `PROCESS-NAME`, `PROCESS-PATH`,
  `UID`, `NETWORK`, `MATCH`. Действия: outbound, `DIRECT`, `REJECT`,
  `REJECT-DROP`, `HIJACK-DNS`.
- **Протоколы, написанные с нуля:** `direct`, `http` (CONNECT), `socks5`/`socks5h`,
  `shadowsocks` (AEAD: ChaCha20-Poly1305, AES-128/256-GCM), `trojan`.
  Дополнительно: `vless` (tcp/ws), `vmess` (AEAD, `alterId: 0`) — ⚠ не сверены
  с живым Xray-сервером.
- **SSH-туннель** через локальный SOCKS5 системного OpenSSH (`ssh -D`).
- **Собственный резолвер.** Стратегии `fake-ip` (подмена на 198.18.0.0/16) и
  `redir-host`; кэш, fallback на DoH. Перехват локального DNS при этом не
  реализован: резолвер используется движком и health-check'ом.
- **Geo-наборы** — текстовые списки CIDR и доменов, обновление по URL с
  проверкой `sha256`.
- **Группы** типов `select`, `url-test`, `fallback`, `load-balance`, включая
  вложенность.
- **Применение с откатом.** Снапшот системного состояния → валидация →
  проверка живым соединением → применение → health-check → откат при ошибке.
- **Графическое приложение** на Tauri 2: тёмная и светлая темы, русский и
  английский, семь экранов, подтверждение опасных действий, диагностика.
- **`pfu-cli`** для headless-конфигурации: `status`, `connect`, `doctor`,
  `rules`, `proxies`, `metrics`, `geo`, `logs`, `apply`.
- **Пакет `.deb`** с `postinst`/`prerm`/`postrm`, systemd-юнитами и polkit.
- **Документация** на русском и английском: архитектура, схема конфигурации,
  IPC-контракт, протоколы, чек-лист тестирования.
- **117 модульных тестов** на движок, rule engine, протоколы и конфигурацию.

### Ограничения
- `vless` и `vmess` не проверены против живого сервера.
- `trojan` и `ssh` не пересылают UDP; для QUIC и игр нужен SOCKS5h или
  Shadowsocks.
- TUN-режим есть в конфигурации, но не реализован. Перехват nftables
  покрывает TCP системы и UDP форвардинга; локальный UDP (DNS, QUIC) идёт
  напрямую.
